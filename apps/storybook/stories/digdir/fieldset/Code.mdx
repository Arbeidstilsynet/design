It is common to get confused between fieldset and field.
A good rule of thumb is that **fieldset is a set of fields**

<Canvas of={FieldsetStories.Preview} sourceState="shown" />

## Usage

Use `ds-fieldset` on the `<fieldset>` element, and place `<legend>` and `<ds-field>` elements inside.

```html
<fieldset class="ds-fieldset">
  <legend class="ds-label">Do you accept the terms?</legend>
  <!-- your fields -->
</fieldset>
```

## Examples

### With checkbox or radio

Build the group with [checkbox](?path=/docs/designsystemet-no-checkbox--code) or [radio](?path=/docs/designsystemet-no-radio--code) as children of `<fieldset>`. This also applies when the group has only one element.

<Canvas of={FieldsetStories.WithCheckbox} />

### With validation message

When a [validation message](?path=/docs/designsystemet-no-typography-validationmessage--code) with `data-field="validation"` is a child of `<fieldset>`, the containing `<ds-field>` elements will
automatically be updated to reflect the validation state.

<Canvas of={FieldsetStories.WithValidation} />

### Multiple field types

A fieldset can also group other fields, for example [field](?path=/docs/designsystemet-no-field--code) with [input](?path=/docs/designsystemet-no-input--code) and [select](?path=/docs/designsystemet-no-select--code).

<Canvas of={FieldsetStories.WithFields} />

### Readonly

Fields with the `readonly` attribute are included in the tab order. Users can copy the content but not edit it. Information is included when the form is submitted.

`Readonly` fields can be confusing for some users. Not everyone will understand why they cannot change the content of the field. We therefore recommend avoiding `readonly` as much as possible.

The component will inherit from the closest parent where these are set.
